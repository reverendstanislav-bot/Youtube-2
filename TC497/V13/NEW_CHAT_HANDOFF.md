## Episode facts / narrative

Central question:
**Why did the U.S. Army build a 572-foot train that needed no tracks — and why did it scrap it even though the machine worked?**

Angle:
TC-497 was not simply a failed crazy machine. It was a serious solution to a real logistics problem that became obsolete when a better technology changed the problem.

Emotional line:
**America built a giant machine for a world without roads. The machine worked — but the future changed faster than it could be used.**

Later payoff:
**It wasn't defeated by the desert. It was defeated by the sky.**

Do not reveal helicopters too early.

Core facts:
- 572 ft final described configuration
- 13 units total
- 54 driven wheels
- welded aluminum
- 6-person crew
- about 150 tons cargo
- about 10 ft tires
- about 20 mph, about 400 mi official retrospective
- formal Project OTTER tests in 1963
- performed well overall
- could not negotiate about a 12 ft dune slip face
- heavy-lift helicopters such as S-64 made the concept obsolete
- sold as scrap in 1968
- control car survives at Yuma
- 1961 Army considered a nuclear-powered overland vehicle concept, but TC-497 itself used gas turbines; never call TC-497 nuclear-powered

## Editing system that must be preserved

Core goal:
**Do not animate pictures. Edit static material so the viewer stops experiencing it as static material.**

Rules:
- base unit = shot / semantic beat, not asset duration
- picture logic: `WIDE → DETAIL → EVIDENCE → EXPLANATION → WIDE PAYOFF`
- no metronomic cadence
- no random FFmpeg slideshow
- no perpetual Ken Burns
- no shake
- no generic split-screen
- 80–90% cuts may be hard cuts when neighboring images match in meaning / geometry / tone
- dissolve only for actual visual-language changes
- documents: establish → exact evidence/detail → visual confirmation
- archive = evidence, not decoration
- typography = rare beat, not constant UI
- subtitles = phrase-level, word timings as source of truth
- no caption blackout windows
- no karaoke active-word flashing
- one still may support multiple purposeful framings, but never `wide → tight → wide` oscillation inside one semantic beat
- one frame should have at most one directed change
- stillness is valid

Pipeline:
**FFmpeg for source preparation + common grade → Remotion for compositing/edit layer → FFmpeg for final QC/encode.**
